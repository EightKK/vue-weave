# Changelog

## Unreleased

This is the first stable release. From here on the package follows SemVer as defined in [Compatibility and versioning](docs/api.md#compatibility-and-versioning), and it is published on npm (`npm install vue-weave`). The changes below fix data-correctness and compatibility problems found in the pre-release review; the ones that change results or types are listed under "Breaking changes", each with who is affected and what to do.

### Breaking changes

- `fromICalendar` now resolves a `TZID` local time that a daylight-saving change skips as RFC 5545 section 3.3.5 requires: with the UTC offset in effect before the change. `DTSTART;TZID=America/New_York:20070311T023000` is now 07:30 UTC (local 03:30) instead of 07:00 UTC. This applies to DTSTART, DTEND and the end of a day or week `DURATION`. A repeated local time still takes its first occurrence. Who is affected: anyone who imports `.ics` files with `TZID` times that fall in a skipped hour; re-importing such a file gives a start or end up to one gap length (usually one hour) later than 0.6.0 did, so events imported with 0.6 and re-imported with 1.0 can differ. What to do: re-import those files if you stored 0.6.0 results and need the RFC times. `buildWorkPeriods`, calendar bands and editing keep moving a skipped time to the change itself. `toICalendar` writes UTC and is unaffected.
- `comparePlans` now throws when a given successful `result` does not match the task set of its `input`: an active task is missing or listed twice, or `inactiveTaskIds` does not list exactly the inactive tasks (subtasks of an inactive summary included). A result calculated before a task was added, removed or (de)activated used to be compared as a complete plan, with the new task `unscheduled` and a stale finish. Who is affected: callers who pass a precomputed `result` that does not exactly match the input (stored, cached or hand-built results). What to do: recalculate the result whenever its input changes, or omit `result` and let `comparePlans` calculate it. Only task sets are checked; a result for an earlier version of the same tasks (a changed duration, say) is still not detected, so keep a shared revision if you store results separately from their input.
- `parseFieldValue` with a `select` spec that has `multiple: true` now always returns an array, also for a single entry (`'a'` → `['a']`, was `'a'`). GanttChart's built-in field input therefore proposes arrays for such columns. Who is affected: code reading `field-edit` `after` or `parseFieldValue` results for multiple selects. What to do: expect an array.
- `formatFieldValue` for a `time` field with `timeZone` now appends the offset to a wall time that occurs twice (for example `2026-11-01 01:30 -05:00` in `America/New_York`), so the text parses back to the same instant. Who is affected: code that displays, compares or parses this text itself. What to do: accept the `±HH:MM` suffix.
- GanttChart row heading text (`vw-row-content`) is now a focusable `role="button"`, named by its content, with one Tab stop for the heading column (see "Added"). Who is affected: tests that look up buttons with loose or regular-expression names (for example `getByRole('button', { name: /^Task/ })`), which can now also match a heading. What to do: use exact names, or exclude the heading.
- `setWindowedView`, `retryWindowedData` and `windowedCoverage` now throw `RangeError` for a window whose chunk indices are not safe integers (finite times too far from `origin` for `chunkSize`), instead of looping without end. `setWindowedView` also throws `RangeError` when the chunk boundaries `origin + k·chunkSize` of the view are not distinct finite numbers, and `windowedCoverage` throws when the window's cell count exceeds `Number.MAX_SAFE_INTEGER`. `useWindowedData` reports these views through `error`. Who is affected: only views with extreme ranges or origins, which previously hung. What to do: use a larger `chunkSize` or an `origin` closer to the window.
- Types only: `ScheduleGraph` (returned by `scheduleToGraph`) now types `nodes` as `NetworkNode<ScheduleGraphNodeData>[]` and `edges` as `GraphEdge<ScheduleGraphEdgeData>[]`, so node and edge `data` (critical flag, early dates, lag) can be read without casts. The arrays still assign to `NetworkNode[]` and `GraphEdge[]`. Who is affected: code that pushes items with other data into `graph.nodes` or `graph.edges`. What to do: copy the arrays into your own `NetworkNode[]`/`GraphEdge[]` first.

### Added

- GanttChart rows can be activated from the keyboard. Enter or Space on a row heading emits `target-activate` with source `keyboard`. ArrowUp, ArrowDown, Home and End move between headings, through a single roving tab stop. Controls inside a `row` slot keep their own keys.

### Fixed

- The type declarations of `useTimelineView` (`state`) and `useEditTransaction` (`historyReset`) no longer use the two-argument `ShallowRef<T, T>`, which Vue 3.5.0 does not declare, so strict TypeScript projects on the minimum supported Vue (`^3.5.0`) no longer fail with TS2707.
- GanttChart cell inputs (plain and typed) and the Escape handling around `cell-editor` leave Enter and Escape of an input method composition (`isComposing` or keyCode 229) to the input method. Confirming a Japanese conversion no longer commits the half-typed text or resets the input; a later Enter commits.
- Committing unedited text in a typed field cell, or `commit(value)` with the current value, ends the edit with no `field-edit` and no validation. Values whose text did not parse back no longer produce changes.
- `parseFieldValue` reads `select` labels as well as values, so the text `formatFieldValue` shows can be committed again. Duplicate labels are rejected as ambiguous with a `choice` error and formatted as values. Labels containing commas are read whole in multiple selects.
- Time fields with `timeZone` round-trip repeated wall times: format then parse gives back the same instant. Typed text without an offset still resolves to the earlier occurrence.
- `useAsyncGraphLayout` now holds the results and failures of the frame being computed apart from its reuse cache. With `cacheSize: 0` or `1` a frame no longer re-requests the same layouts forever without being shown. A failed request is no longer silently repeated when its other scope succeeds, so `display.source === 'layout'` no longer appears next to a stale `error`. A failed frame is requested again when the input changes. `cacheSize` now only sets how many layouts are kept for reuse by later inputs.
- `graphLayoutWorkerAdapter` rejects a response whose `requestId` and `inputKey` match but whose `scope` differs. It removes its `message` and abort listeners however a request ends, including when posting the request to the Worker throws (the request then rejects with that error) and when the cancel message cannot be posted.
- `setWindowedView` no longer walks every chunk of the time range for a view with an empty `rowIds`; such a view requests nothing.
- `windowedCoverage` no longer counts unloaded cells one at a time. It computes `total` from the chunk and row counts and counts only the recorded cells, so checking a whole plan over a wide range stays cheap.
- `useWindowedData` no longer throws when the first read of `condition` fails (a getter that throws, or a value that is not a string), including during server rendering. That failure, and a `view` or `condition` getter that throws later, which the watcher used to swallow, is reported through `error`, and the view is requested again once the value is valid.
- `parseWeaveSnapshot` and `restoreWeaveSnapshot` of timeline snapshots, and `projectTimelineView` without `laneCount`, no longer throw `RangeError: Maximum call stack size exceeded` for timelines with very many bars (for example 200,000). GanttChart's `fitToBars`, NetworkGraph's collapsed-group moves, group frames and actuals diagnostics append large lists with loops for the same reason.

### Documentation

- `docs/api.md` adds "Compatibility and versioning", which defines what 1.x SemVer covers (exported names and types, component props, events, slots and exposed methods, documented `--vw-*` custom properties, the snapshot format) and what it does not (exact error message texts, emitted `vw-` classes, DOM structure and server-rendered markup). Error message formats are documented as current behaviour; match on the error class or diagnostic `code`/`id`.
- The READMEs put installation from npm first, explain the stylesheet import, TypeScript CSS declarations and core-only installs (Vue stays a required peer; use `--omit=peer` to leave it out), and use image and document links pinned to the release tag so they work on npmjs.com. The GitHub Release tarball remains an offline alternative.
- CONTRIBUTING describes the manual npm publication of the verified release tarball and the `dist.integrity` check against its local SHA-512.

### Packaging

- `npm run test:package` type-checks the packed library against both Vue 3.5.0 (the minimum of the peer range) and the pinned development Vue.

## 0.6.0 - 2026-11-19

This is a minor release because of the changes under "Breaking changes": error messages of input checks are unified, an ID must be a non-empty string everywhere, `layoutGridGraph` has a new default `columnGap`, and `graphRectsIntersect` no longer counts touching rectangles. Each entry below says who is affected and what to change.

### Breaking changes

- Graph layouts: every built-in layout (layered, tree, radial, circular, grid, concentric, swimlane, force, flow and incremental) now reports an invalid numeric option in one format that names the option, the rule and the value: `RangeError('<option> must be <rule> (got <value>)')`, with the rules `a finite number > 0`, `a finite number ≥ 0`, `a finite number`, `an integer ≥ 1`, `a finite number in [0, 1]` and `a safe integer`. Before, the texts varied, for example `columnGap must be finite and positive (spacing may be zero)`, `rowGap must be finite and nonnegative (node sizes positive)`, `nodeWidth and nodeHeight must be finite and positive` or `crossingSweeps must be a positive integer`; now `columnGap must be a finite number ≥ 0 (got -1)` and `crossingSweeps must be an integer ≥ 1 (got 0)`. The error class (`RangeError`) and the accepted values are unchanged. What to do: update code or tests that match these messages.
- `layoutGridGraph`: the default `columnGap` is 50 (was 40), the default of every other layout, so a grid without an explicit `columnGap` is 10 units wider per column gap. What to do: pass `columnGap: 40` to keep the earlier geometry.
- `layoutLayeredGraph`: same-rank edges (inside a cycle) and self-loops turn `min(24, max(6, columnGap / 2))` units past the box, as in the tree and swimlane layouts (was `min(24, columnGap / 2)`). Only a `columnGap` below 12 changes the drawing: the turn stays 6 units out instead of shrinking towards the box, and the layout can grow by up to 6 units along the flow when such an edge leaves the last rank. What to do: nothing, unless you compare paths of such layouts exactly.
- `graphRectsIntersect(a, b)`: rectangles that only touch, along an edge or at a corner, no longer intersect; the test now uses open intervals (`a.x < b.x + b.width && b.x < a.x + a.width`, and the same for y), compared exactly. A zero-size rectangle intersects a rectangle whose interior it passes through, not one whose border it lies on. `cullGraphElements` (and so `cullOffscreen`) still keeps elements whose bounds touch the view, because their strokes can still draw into it. What to do: if you need touching rectangles to count, test `a.x <= b.x + b.width && b.x <= a.x + a.width` (and y) yourself.
- `GraphTreeLayoutOptions`, `GraphSwimlaneLayoutOptions` and `GraphIncrementalLayoutOptions` now extend `GraphLayoutOptions` instead of declaring `direction`, `nodeWidth`, `nodeHeight`, `columnGap`, `rowGap` and `padding` themselves. Names, types and optionality are unchanged, so every existing object literal still type-checks; code that augments one of these interfaces with a conflicting declaration of a shared field must now match `GraphLayoutOptions`.
- One ID rule and one set of error texts for the planning, timeline and data core (see [Validation and errors](docs/api.md#validation-and-errors)). An ID must be a non-empty string, unique within its collection; any other value is invalid and throws an `Error`. Values that the looser check `!id` let through now throw `Invalid <kind> ID: <value>`: numbers other than 0 (such as `5`), `true` and objects as task, dependency and calendar IDs in `scheduleTasks`, `propagateEdit`, `rescheduleFromStatusDate`, `levelResources` (also resource IDs) and the snapshot functions that run the scheduler; task and resource IDs in `calculateResourceLoad`; row, bar and dependency IDs in `validateTimelineData` (and so GanttChart's `validation-error`, `renderTimelineSvg` and snapshots); marker and load row IDs in `renderTimelineSvg`. `scheduleToGraph`, which only checked dependency IDs for duplicates, now rejects every invalid one, `''` and `undefined` included. `createTimelineRowTree`, and with it `timelineWbsCodes`, `moveTimelineRow`, `indentTimelineRow`, `outdentTimelineRow`, `timelineRowPosition`, `timelineCsvTable` and `renderTimelineSvg`, now also rejects the row IDs `0`, `null` and `undefined` and numbers. `buildPlacementInput` rejects an assignment whose `resourceId` is not a non-empty string (`Unknown resource in assignment: <value>`). A `null` entry in the tasks, dependencies or calendars of `scheduleTasks`, or in the tasks or resources of `calculateResourceLoad` and the resources of `levelResources`, throws `Invalid <kind> ID: undefined` instead of a `TypeError`. The interchange, windowed data and snapshot checks already used the strict rule; only their texts change.
- Invalid and duplicate IDs have separate messages everywhere, `Invalid <kind> ID: <value>` and `Duplicate <kind> ID: <id>`, where several functions said `Invalid or duplicate …`. For example `Invalid or duplicate task ID: a` → `Duplicate task ID: a`; `Invalid or duplicate schedule dependency: d1` → `Duplicate dependency ID: d1`, `Invalid dependency ID: 5` or, for an unknown `from` or `to`, `Unknown dependency endpoint: d1` (as `buildPlacementInput`, `projectResourceTimeline`, `validateTimelineData` and `scheduleToGraph` already said); `Invalid or duplicate resource: r` → `Duplicate resource ID: r`; `Invalid or duplicate workload task: a` → `Duplicate task ID: a`; `Invalid or duplicate row IDs` → `Duplicate row ID: r1`; `Invalid baseline set ID on bar: x` → `Invalid baseline set ID: "" (bar x)`; `Duplicate baseline set p on bar x` → `Duplicate baseline set ID: p (bar x)`; `Duplicate baseline set ID in baselineIds: p` → `Duplicate baseline set ID: p (baselineIds)`; `Invalid or repeated baseline set ID for baseline 1: b` → `Invalid baseline set ID: b (baseline 1)` or `Duplicate baseline set ID: b (baseline 1)`; `Windowed data items need a non-empty string ID` → `Invalid windowed data item ID: undefined`; `Duplicate item ID in one response: i` → `Duplicate windowed data item ID: i (in one response)`. Snapshot diagnostics for an invalid ID say `Invalid <kind> ID: <value>` instead of `Must be a nonempty string`. An empty ID now shows as `""` in messages.
- Assignments are checked by one shared checker in `calculateResourceLoad`, `levelResources`, `buildPlacementInput`, `projectResourceTimeline`, `toMsProjectXml`, `resourceLoadFromMsProject` and `comparePlans` (and `proposeResourceAssignment` for duplicates in its state), with the same texts: `Unknown resource in assignment: <id>`, `Unknown task in assignment: <id>` (with the `options.inactiveTaskIds` hint only from `calculateResourceLoad`) and `Duplicate assignment of task <task> to resource <resource>`, which replaces `Duplicate resource assignment for task: <task>` (and `…: <task>, <resource>`) and `Unknown task or resource in assignment: <task>, <resource>`. The duplicate check keys pairs by nested maps, so IDs that contain separator characters never collide.
- `renderTimelineSvg` throws an `Error` (not a `RangeError`) for an invalid or duplicate marker ID: `Invalid marker ID: <value>` or `Duplicate marker ID: <id>`; a marker time that is not finite is still `RangeError: Invalid timeline marker: <id>`. GanttChart's marker prop check now says the same (see the component bullets below).
- If you match on error messages: replace `/Invalid or duplicate/` and `/duplicate …/` patterns with the separate `Invalid <kind> ID:` and `Duplicate <kind> ID:` texts (note the capital D), `Invalid or duplicate schedule dependency` with `Invalid dependency ID`, `Duplicate dependency ID` or `Unknown dependency endpoint`, and `Duplicate resource assignment for task` and `Unknown task or resource` with the assignment texts above. Better, match on the error class and the ID rather than the full text.
- GanttChart and NetworkGraph prop checks follow the same rule as the core: a RangeError for invalid numbers and geometry and for an unknown value of a string option, an Error for bad references, invalid or duplicate IDs and cycles; GanttChart's own ID checks use the strict ID rule and the `Invalid <kind> ID` and `Duplicate <kind> ID` texts (see [Validation and errors](docs/api.md#validation-and-errors)). How each error is surfaced (GanttChart's `validation-error` plus the rethrow, NetworkGraph's throw while rendering), the order of the checks and the rendering of valid props are unchanged.
- GanttChart, error class: overlapping, empty or non-finite `headerBands` (also those of a zoom preset) are a RangeError (was Error), with the same text `Timeline bands must be finite, ordered and nonoverlapping`; a marker whose `time` is not finite is `RangeError: Invalid timeline marker: <id>` (was Error, same text); a column whose `width` is not finite and positive is `RangeError: Invalid timeline column width: <id>` (was `Error: Invalid timeline column: <id>`). These are the class and text `renderTimelineSvg` uses.
- GanttChart, ID texts: invalid and duplicate IDs have separate messages. `Invalid or duplicate load row ID: l` → `Duplicate load row ID: l`; `Invalid or duplicate zoom preset: p` → `Duplicate zoom preset ID: p`; `Invalid timeline column: c` (for an ID) → `Duplicate column ID: c`; `Invalid timeline marker: m` (for an ID) → `Duplicate marker ID: m`; an empty ID gives `Invalid load row ID: ""`, `Invalid zoom preset ID: ""`, `Invalid column ID: ""` or `Invalid marker ID: ""`. All stay Error.
- GanttChart, inputs that are now rejected: a marker, column, zoom preset or load row ID that is not a string (such as `3` or `true`), which the looser `!id` check accepted and rendered, is now reported through `validation-error` (`Invalid marker ID: 3`); a `null` entry in `loadRows` gives `Invalid load row ID: undefined` instead of a TypeError. What to do: pass string IDs, for example `String(id)`.
- NetworkGraph, error class: an unknown `background` is `RangeError: Unknown NetworkGraph background: <value>` (was Error, same text), like an unknown `edgeStyle` or `routingPolicy`; a custom `layout` result without positive finite dimensions is a RangeError (was Error, same text `A custom layout must return positive finite dimensions`); `Missing or invalid layout box: <id>` is split into `Missing layout box: <id>` (Error) for a node without a box and `Invalid layout box: <id>` (RangeError) for a box without finite coordinates and a positive size, the texts of `validateGraphLayoutResponse`. Its group, node, edge and port checks take the graph texts described below.
- If you match on component messages: replace `/Invalid or duplicate (load row|zoom preset)/`, `/Invalid timeline column/` and ID matches on `/Invalid timeline marker/` with the `Invalid <kind> ID:` and `Duplicate <kind> ID:` texts above, `/Missing or invalid layout box/` with `/layout box: /`, and checks such as `error.constructor === Error` or `name: 'Error'` for header bands, marker times, column widths, `background` and custom layout geometry with RangeError.
- Graph core and NetworkGraph, IDs: the ID rule and texts above now also cover the graph side. Node, edge, named port, group and export group IDs, and the IDs of view binding entities and targets, must be non-empty strings, unique within their collection (port IDs within their node), and are reported as `Invalid <kind> ID: <value>` or `Duplicate <kind> ID: <id>` (Error, as before). Before → after: `Graph node IDs must not be empty` → `Invalid graph node ID: ""`; `Graph edge IDs must not be empty` → `Invalid graph edge ID: ""`; `Invalid graph port on node: a` for a port ID → `Invalid port ID: "" (graph node a)` or `Duplicate port ID: p (graph node a)` (the old text stays for an invalid direction or offset); `Invalid graph group: g` for a group ID → `Invalid graph group ID: ""` or `Duplicate graph group ID: g` (the old text stays for a group without nodes); `Invalid or repeated group member: a` → `Unknown node in graph group g: a` or `Duplicate group member ID: a (graph group h)`; `Invalid or duplicate export group: g` → `Invalid export group ID: ""` or `Duplicate export group ID: g`; `createId returned an empty node ID for: a` → `Invalid graph node ID: "" (createId for a)` and `Cloned node ID is already in use: c` → `Duplicate graph node ID: c (createId for a)` (`graph edge` for edges); `A graph layout request needs a nonempty requestId` → `Invalid graph layout request ID: ""`; `Invalid entity reference: kind and id must be non-empty strings` for an invalid ID → `Invalid entity ID: <value>` (the old text stays for an invalid kind); `Invalid view target` for an invalid ID → `Invalid view target ID: <value>`; `Invalid load target: resourceId must not be empty` → `Invalid resource ID: <value> (load target)`. A `null` entry in `groups` gives `Invalid graph group ID: undefined` instead of a TypeError. NetworkGraph's group checks and `collapseGraphGroups` now share one implementation, so the same defect gives the same text in both.
- Graph core, unknown references: one shape, `Unknown <kind> in <owner>: <value>`, as in `Unknown resource in assignment: <id>`, where the owner is what holds the reference. `Unknown endpoint on graph edge: e` → `Unknown node in graph edge e: zz`, which names the missing node (`from` is checked before `to`), in `indexGraph` and every function that calls it, `collapseGraphGroups`, `traverseGraph`, `routeGraphEdges`, NetworkGraph and graph snapshot diagnostics; `Invalid port on graph edge: e` for a port its node does not have → `Unknown port in graph edge e: q` (the old text stays for a port whose `direction` forbids that end); `Unknown parent group: p (group g)` → `Unknown parent group in graph group g: p`; `Unknown collapsed group: x` → `Unknown group in collapsedIds: x`; `Unknown root node ID: x` (`layoutTreeGraph`, `layoutRadialGraph`) → `Unknown node in roots: x`; `Unknown graph node ID: x` (`shortestGraphPath`) → `Unknown node in fromId: x` or `Unknown node in toId: x`. `Unknown node in graph deletion`, `Unknown edge in graph deletion` and `Unknown node in graph clone` already had this shape; like every reference text they now show an empty ID as `""`.
- Graph core and NetworkGraph, inputs that are now rejected: a node, edge or port ID that is not a string (such as `5`, `true` or an object), which the looser `!id` checks accepted, now throws in `indexGraph` and every function that validates a graph through it: `layoutLayeredGraph`, `layoutTreeGraph`, `layoutRadialGraph`, `layoutCircularGraph`, `layoutGridGraph`, `layoutConcentricGraph`, `layoutForceGraph`, `topologicalOrder`, `findGraphCycles`, `shortestGraphPath`, `filterGraph`, `graphComponents`, `graphDegreeCentrality`, `graphBetweennessCentrality`, `graphPageRank`, `detectGraphCommunities`, `graphDeletion`, `removeGraphElements`, `cloneGraphElements` and `renderGraphSvg`; so does an edge ID in `traverseGraph`, a group ID in `collapseGraphGroups` and `buildGraphLayoutRequests`, an export group ID in `renderGraphSvg`, and a load target `resourceId` in `buildViewBindingIndex`, `resolveEntityRefs` and `resolveLoadTargets`. NetworkGraph no longer renders such IDs in `nodes` (also with a custom `layout`), `edges`, node `ports` or `groups`; it throws while rendering, as for other invalid props. The types already declare these IDs as `string`, so typed code is unaffected. What to do: pass string IDs, for example `String(id)`.
- `renderTimelineSvg` columns: an invalid or duplicate column ID gives `Invalid column ID: <value>` or `Duplicate column ID: <id>` (was `Invalid timeline column: <id>` for both), the texts and the strict rule of GanttChart, which now runs the same column, header band, marker and load row checks as `renderTimelineSvg`; a column ID that is not a string (such as `7`) now throws. A width that is not finite and positive is still `RangeError: Invalid timeline column width: <id>`.
- GanttChart `snap` and `minDuration`: `RangeError: Invalid snap or minDuration` is split into `snap must be finite and positive` and `minDuration must be finite and positive` (the active zoom preset's `snap` counts as `snap`; when both are invalid, the snap error is reported). `editTimeRange` uses the same texts: `Editing requires a finite displacement and positive snap/minimum duration` → `delta must be finite`, `snap must be finite and positive` or `minDuration must be finite and positive`, checked in that order. The class (RangeError), the accepted values and the order relative to the other checks are unchanged.
- If you match on graph, column or snap messages: replace `/must not be empty/` with `/^Invalid graph (node|edge) ID: /`; `/Unknown endpoint/` with `/^Unknown node in graph edge /`; `/Invalid port on graph edge/` (for unknown ports) with `/^Unknown port in graph edge /`; `/Invalid graph group/` (for IDs) with `/graph group ID: /`; `/Invalid or repeated group member/` with `/^Unknown node in graph group |^Duplicate group member ID: /`; `/Unknown parent group: /` with `/^Unknown parent group in graph group /`; `/Unknown collapsed group/` with `/^Unknown group in collapsedIds: /`; `/Unknown root/` with `/^Unknown node in roots: /`; `/Unknown graph node/` with `/^Unknown node in (fromId|toId): /`; `/createId returned/` and `/already in use/` with `/^(Invalid|Duplicate) graph (node|edge) ID: .* \(createId for /`; `/Invalid or duplicate export group/` with `/export group ID: /`; `/requestId/` with `/^Invalid graph layout request ID: /`; `/Invalid entity reference/`, `/Invalid view target/` and `/resourceId must not be empty/` for IDs with `/^Invalid (entity|view target|resource) ID: /`; `/Invalid timeline column:/` with `/^(Invalid|Duplicate) column ID: /`; and `/snap or minDuration/` and `/Editing requires/` with `/^(delta|snap|minDuration) must be finite/`.
- Changes to APIs added in this release cycle (not breaking for 0.5.0 users): `comparePlans` validates each side with the scheduler's own rules, also when a `result` is given, and appends the side to every error of that side, for example `Duplicate task ID: a (current plan)` or `Invalid task duration: a (candidate plan)`; its own messages no longer repeat the label (`The candidate plan needs an input` → `A plan needs an input (candidate plan)`, `Invalid schedule result of the current plan` → `Invalid schedule result (current plan)`). A cycle or an infeasible plan is still a result state. `rescheduleFromActuals` reports an invalid actual interval with the scheduler's message for the same defect plus ` (actual interval of task <id>)`, for example `Actual intervals must align with the horizon and quantum: a` → `Scheduling dates must align with the horizon and quantum (actual interval of task a)`, `Actual intervals need finite start and end times: a` → the same alignment message, `Actual intervals must end after they start: a` → `Working periods must have finite integer endpoints and positive length (actual interval of task a)` and `Actual intervals must lie inside the schedule range: a` → `Scheduling dates must lie inside the schedule range (actual interval of task a)`; overlaps, future and off-calendar actuals and finished tasks with remaining work stay diagnostics with the same codes. Marker ranges, windowed data, the iCalendar import, the MS Project calendars, resources and assignments and `planBaselines` use the texts above.
- `PlacementDiagnostic` is now the union `PlacementPredecessorDiagnostic | PlacementSummaryDiagnostic`, discriminated by `code`, because `buildPlacementInput` can report `unplaced-subtasks` for summary tasks. Plans without `parentId` never produce it, but TypeScript code that reads `predecessorId` or `dependencyId` of a `PlacementDiagnostic` no longer type-checks. What to do: check `code === 'unplaced-predecessor'` first.

### Added

#### NetworkGraph

- Obstacle-avoiding orthogonal routing, opt-in: the `avoidNodes` prop and the `avoidNodes` option of `routeGraphEdges` (`true` or a `GraphObstacleAvoidance` with `clearance`, default 8, and `bendPenalty`, default 24) route orthogonal edges without waypoints around every node box, collapsed-group proxies included, leaving and entering on the same sides as before. Waypoints keep their precedence, self-loops and clear bypass lanes are kept, and an edge without a route around the boxes keeps the plain orthogonal route. Drag and resize previews and `exportSvg`/`exportPng` draw the same routes; the previews also reroute the orthogonal edges without waypoints whose saved route meets the old or new clearance area of a changed box, found with a spatial index of the saved routes, so a route moves out of the way of a box dragged across it during the drag rather than only after the drop (past 32 such edges in one frame, they follow on the drop). The new `findOrthogonalRoute(from, to, obstacles, options)` (with `GraphRouteEnd`) exposes the router: A* over a sparse grid of lines between box edges, deterministic and bounded. Without the option, routes are unchanged.
- Port rules, opt-in: the `connectionRules` prop (`GraphPortRules`: per-port `GraphPortRule` with `type`, `direction` `in`/`out`/`both` and `maxConnections`, a rule per node for connections without a port, and a `default`) checks every connect and reconnect proposal, pointer and keyboard, before `validateConnection`; a broken rule is rejected with a readable reason through `connect-rejected` and the live region, and a proposal that passes still goes to `validateConnection`. While a connection is in progress, handles get `vw-is-valid-target` or `vw-is-invalid-target` (invalid ones also an `aria-description` with the reason), styled with the new `--vw-connect-valid` and `--vw-connect-invalid` variables and distinguishable without colour. Rules live outside the node data, so existing data and types are unchanged; without the prop, markup and behaviour are unchanged. #### Graph core (`vue-weave/core`)

- Swimlane layout for process flows: `layoutSwimlaneGraph(nodes, edges, { lanes, laneOf, direction, ... })` puts every node in its own lane's band, with ranks from the layered layout (cycles and self-loops share a rank), lanes in the caller's order (never reordered; empty lanes keep a band) and barycenter ordering inside a lane, with the shared layout defaults (nodes 144 × 58, `columnGap` 50, `rowGap` 24, `padding` 20). It returns a `GraphSwimlaneLayout` (a `GraphLayout` plus `lanes`: band, header, `index` and `nodeIds` per lane). A node without a lane or with an unknown lane throws an `Error`. `graphSwimlaneAt(lanes, pointOrBox)` tells which lane a point or box centre falls in, so an application can turn a `node-move` proposal into a lane change. `renderGraphSvg` takes the same `lanes` option as the NetworkGraph prop. Types `GraphSwimlaneSpec`, `GraphSwimlaneBand`, `GraphSwimlane`, `GraphSwimlaneLayout` and `GraphSwimlaneLayoutOptions`.
- Quantity flow (Sankey) projection: `layoutFlowGraph(nodes, edges, { quantity, unit, displayUnit, direction, nodeThickness, nodeGap, rankGap, scale, ... })` returns a `GraphFlowLayout`, a `GraphLayout` for the `layout` prop plus `nodes` (`GraphFlowNode`: box, rank, `inflow`, `outflow`, `difference`, `value` and the reference totals), `bands` (`GraphFlowBand`: edge ID, quantity, unit, `thickness = quantity × scale` on one scale for the whole picture, drawn `width`, source and target sides and offsets, centre-line path and a label such as `Cut → Inspect: 60 pcs`) and `excluded` (`GraphFlowExcludedEdge`). Ranks and orders come from the layered layout with barycenter sweeps; bands are stacked along each side by the position of their other end. The unit is required, and edges in another unit than the displayed one are listed in `excluded` and never added. Totals are reported as given, never balanced. A quantity must be a finite number of at least 0 (`RangeError`); a zero keeps a hairline band. Edges that close a cycle and self-loops become `reference` bands routed below the ranks and counted apart from the totals; loops are not unrolled by period. `scale` is `{ pixelsPerUnit }` or `{ fitExtent }` (`GraphFlowScale`). `graphFlowBands(flow)` builds the band map for the NetworkGraph `edgeBands` prop, and `renderGraphSvg` takes the same `edgeBands` option. - Stable incremental placement: `layoutGraphIncrementally(nodes, edges, positions, options?)` (`GraphIncrementalLayoutOptions`, `GraphKnownPosition`) returns a complete `GraphLayout` (`GraphIncrementalLayout`, with `placedIds`, `movedIds` and `fallbackIds`) in which every positioned node keeps its box exactly and each new node is placed on the flow side of its placed neighbours (after predecessors, before successors, in all four directions) in free space, keeping the column and row gaps; chains of new nodes follow their dependency order, components without a positioned node are laid out as a layered block next to the others, and positions of unknown IDs are ignored. `fixedIds` pins nodes; the relaxed mode `maxDisplacement` (default 0) may push unfixed blocking nodes across the flow by a bounded distance; new boxes stay nonnegative unless `allowNegative`; `previousLayout` keeps the paths of edges between unchanged boxes. #### Scheduling and resources

- Summary tasks in the scheduler: `ScheduleTask.parentId` makes a task a subtask, and a task that other tasks name as parent is a summary task whose dates are the span of its subtasks. FS and SS links into a summary bind the start of every subtask (FF and SF links into a summary throw an Error, as Microsoft Project does not allow them); links from a summary use its rolled-up start or finish. A summary's `startNoEarlierThan` and `finishNoLaterThan` bind its subtasks; `fixedStart`, `startNoLaterThan`, `finishNoEarlierThan`, `manual` and `mode: 'alap'` on a summary throw an Error. Results mark summaries with `summary: true`, give them the span of their subtasks' latest dates, the smallest float of their subtasks and a critical flag when any subtask is critical, and give subtasks their `parentId`. Unknown parents, parent cycles and links between a summary and its own subtask throw an Error that names the tasks; a dependency cycle through a summary's roll-up is a `cycle` failure. `propagateEdit` refuses to edit a summary, `rescheduleFromStatusDate` frees started subtasks from the start bounds of their summaries, `levelResources` levels the subtasks and gives summaries no load, and `buildPlacementInput` keeps what binds the placed subtasks of an unplaced summary: they move to their nearest placed ancestor and take over the `startNoEarlierThan` and `finishNoLaterThan` of the unplaced summaries they skip, stay inactive below an inactive one, and links into an unplaced summary still bind its placed leaf subtasks (an `unplaced-predecessor` diagnostic when the link comes from an unplaced task). A placed summary that is active but has no placed active leaf subtask is an `unplaced-subtasks` diagnostic (not `ok`) and is left out like an unplaced summary, instead of being scheduled with its own duration. `buildPlacementInput` checks the summary rules on the whole input and throws the scheduler's Error for a rule broken by unplaced tasks too. Plans without `parentId` are scheduled exactly as before. See [Summary tasks](docs/scheduling.md#summary-tasks).
- `PlacementResult.retargetedDependencies` (`PlacementRetargetedDependency`: `id`, `dependencyId`, `summaryId`, `taskId`), present only when not empty: the links of a placement input that replace a link from a placed task into an unplaced summary, one per placed leaf subtask, so that `criticalDependencyIds` and traces map back to the input link.
- `buildPlacementInput` diagnostic `{ code: 'unplaced-subtasks', taskId }` (`PlacementSummaryDiagnostic`) for a placed summary task without a placed active subtask; it comes before the `unplaced-predecessor` entries (now also exported as `PlacementPredecessorDiagnostic`) and makes `ok` false.
- Time-varying resource capacity, opt-in: `ResourceCapacity.capacityPeriods` (`ResourceCapacityPeriod`: `start`, `end`, `capacity`) replaces a resource's `capacity` over fixed half-open intervals; outside them `capacity` applies, and outside the availability `periods` the capacity stays 0. Overlapping, empty or inverted periods and invalid capacities throw a RangeError that names the resource. `calculateResourceLoad` splits its segments where the capacity changes and measures overload against the capacity valid at each time, so GanttChart's capacity line and `renderTimelineSvg` follow it with no new prop; `levelResources` reserves against the same capacity, so leveling and the load calculation agree. Planning snapshots validate the field.
- Assignments for part of a task, opt-in: `ResourceAssignment.workOffset` and `workDuration` limit an assignment to part of the task's working time, measured along its scheduled `work` segments, so the part moves with the task and skips breaks, pauses and splits. A part beyond the work is clipped. `calculateResourceLoad` and `levelResources` count the resource only during the part, `projectResourceTimeline` still shows the whole task on its row and `proposeResourceAssignment` keeps the part on a replacement. New `assignmentWorkPeriods(work, assignment)` returns the part's elapsed periods. Input without the new fields gives the same results as before. See [Compare demand with capacity](docs/scheduling.md#compare-demand-with-capacity).
- Rescheduling from recorded actuals, opt-in: `rescheduleFromActuals(input, statusDate, actuals)` takes recorded actual intervals per task (`TaskActuals`: half-open `intervals`, optional `remainingWork` and `finished`), keeps them exactly as recorded, also on non-working time, and schedules only the remaining work from the status date (or the last actual end, if later) on the task's calendar, links and bounds. The default remaining work is the duration minus the elapsed length of the actuals, at least 0. Started tasks drop their start bounds and incoming FS and SS links and keep FF and SF links, as in `rescheduleFromStatusDate`; finished tasks end at their last actual end. The `RescheduleFromActualsResult` has the forecast `schedule`, the original `plan`, per-task `ActualsTask` entries with separate `actual` and `remaining` work, and diagnostics (`ActualsDiagnostic`: `actual-overlap`, `actual-after-status-date`, `actual-outside-calendar`, `actual-contradiction`, followed by those of the schedule); an infeasible forecast is returned with the actuals kept. Summary, manual and inactive tasks are supported. `rescheduleFromStatusDate` is unchanged. `actualsTimelineBars(result, options?)` (`ActualsTimelineBarOptions`) turns the result into GanttChart bars that show the original plan as a baseline, the recorded actuals as a solid `<label> · actual` bar and the remaining forecast as an outline `<label> · forecast` bar on one row.
- Plan scenario comparison: `comparePlans(current, candidate)` compares two `PlanScenario`s (a `scheduleTasks` input with optional resources and assignments, optional precomputed `result` and `load`, `revision`, `baseRevision` and `partial`) and returns a `PlanComparison` with separate `input` differences (settings, tasks, dependencies, calendars, resources and assignments, with the changed field names) and `result` differences (schedule state per side, final completion, per-task date shifts and critical changes, tasks edited versus moved as a consequence, critical dependencies, `deadline`, `manual-conflict` and `leveling-unresolved` violations gained and lost, and cumulative overload per resource). Cycles and infeasible plans are reported, not thrown; partial plans make the comparison incomplete and a moved base revision marks it stale. `planComparisonTargets` turns compared tasks into view and load targets for the highlight props, and `planBaselines` turns a schedule into a named baseline set. `PlanComparisonTask.deadline` is an optional due time that the scheduler ignores. New types `PlanComparisonTask`, `PlanComparisonInput`, `PlanScenario`, `PlanScheduleState`, `PlanTaskSide`, `PlanFieldChange`, `PlanCollectionDiff`, `PlanAssignmentChange`, `PlanAssignmentDiff`, `PlanInputDiff`, `PlanViolation`, `PlanTaskComparison`, `PlanResourceOverload`, `PlanResultDiff`, `PlanComparison`, `PlanComparisonTargetOptions` and `PlanComparisonTargets`.

## 0.5.0 - 2026-11-17

This is a minor release because of the two type changes under "Breaking changes": TypeScript code that lists every value of `ScheduleReasonKind` or `PlanningDiagnosticCode` needs a new case. Code that runs today behaves the same, since the new values only appear once a plan uses manual tasks. Everything else is additive and opt-in: without the new fields, props and options, results, server markup, routes, exports and accessible names are the same as in 0.4.0.

### Breaking changes

- `ScheduleReasonKind` gains `'manual'`, used in traces (`{ explain: true }`) for the dates of manual tasks.
- `PlanningDiagnosticCode` gains `'manual-conflict'`. `toPlanningDiagnostics` lists each entry of `manualConflicts` as a warning with the task and the link, before unresolved tasks and overloads; with `explain`, its `reasonIds` name the task's `manual` reason. A result without manual conflicts gives the same list as before.

A `switch` or `Record` over every value of either union needs an entry for the new value.

- `timelineFromCsvTable` lets a custom header take precedence over another column's default header whatever the column order, and throws when two custom headers are equal. It reads progress only in plain decimal notation (`0x1` and `1e0` are now rejected) and orders WBS parts of any length exactly.
- `toMsProjectXml` and `toICalendar` throw an Error for a missing project or task name or event summary instead of writing "undefined".
- `rescheduleFromStatusDate` throws a descriptive Error when `progress` is not a Map.
- NetworkGraph compares `groups` and `labels` by value, so new but equal inline literals no longer rebuild the layout or cancel a node drag or pan when the parent re-renders. A real change still cancels the gesture.
- GanttChart compares `range`, `editBounds` and `tickSteps` by value, so new but equal inline literals no longer re-run validation or cancel an in-flight drag. This also prevents an endless render loop when a parent updates state in its `validation-error` handler.
- A second primary pointer of another type (for example a pen next to the mouse) can no longer start or take over a gesture in NetworkGraph or GanttChart while one is in flight. Two-finger pinch is unchanged.
- GanttChart now measures its label column after mounting with invalid data or passing through an error state, so a later `labelWidth` or column change updates which bars are rendered.
- With `cascade`, a change of `dependencies` during a bar drag cancels the drag without a proposal instead of proposing follow-on changes computed from the old dependencies.
- Keyboard focus on a selected NetworkGraph node, or on a node rendered through the `node` slot, now shows a distinct accent outline (Highlight in forced-colours mode). Focused edge and dependency hit areas use an opaque dashed accent stroke with at least 3:1 contrast, distinct from the translucent active and selected bands.
- With `dir="auto"`, NetworkGraph and GanttChart now follow a later change of an ancestor's `dir` attribute and cancel a gesture in flight when the direction changes.

### Fixed

- The demo hides its graph Undo and Redo buttons in the timeline editing example, where they changed the hidden graph and timeline instead of the shown timeline.
- Restore Vue type checking and declaration generation with TypeScript 6.0.x; hold Dependabot's TypeScript 7+ updates pending compatibility with `vue-tsc`.
- Remove the source-only stylesheet import from generated declarations so strict `noUncheckedSideEffectImports` consumers can import the components.
- Report missing row parents and hierarchy cycles through Gantt `validation-error`, render the empty state and recover on valid replacement data.
- Keep empty graph layouts measurable with zero padding in both LR and TB directions.
- Resolve ESM declarations in strict TypeScript NodeNext consumers, including Vue component declarations.
- Report invalid Gantt input through `validation-error(error)` and render the empty state in production. Development builds surface the rethrown error. Validate updated `pixelsPerUnit` and `scale` props.
- Keep a focused Gantt bar rendered outside the visible window and reveal it after an accepted keyboard edit.
- Reuse long-edge routing lanes so graph headroom depends on overlapping edges.
- Expose zoom-control group names and localize graph rejection and edge-selection labels.
- `levelResources` keeps a split task at the start it reserved. Before, an end bound (`finishNoEarlierThan`, FF or SF) could pull the start earlier during the final recalculation, placing work in resource downtime or on capacity taken by another task while `unresolvedTaskIds` stayed empty. Split tasks now always get a `startNoEarlierThan` in `leveledTasks`, and a task whose final work differs from its reserved slices is reported in `unresolvedTaskIds`.
- `graphPathBounds` reads numbers with `e`/`E` exponents (`1e-7` was treated as a command and threw), tracks the reflected control point of S and T, and bounds arcs exactly after SVG radius correction and rotation. Culling and SVG/PNG export no longer drop or clip such edges. Malformed path data, including stray characters and a command without arguments, now throws `Invalid SVG path data`.
- Reconnect handles sit at the drawn edge ends after saved positions swap two nodes or a custom layout picks its own sides. `graphEdgeEndpoint` now takes unnamed endpoints from the drawn path of an edge with an `id`; new `graphPathEndpoints(path)` returns a path's first and last points.
- Fit to view shows the whole graph even when that needs a scale below 0.1. Zoom, pinch, `setViewport` and `focusNode` accept scales down to that fit scale, so a fitted viewport can be restored. The automatic initial view keeps its 0.1 floor.
- Gantt grid lines are drawn at every tick position (new `vw-gantt-grid-line` and `vw-gantt-tick-line` elements) instead of a repeating CSS background, so they match the tick labels and the SVG export on non-linear `scale`s and in right-to-left charts. The tick step is chosen from the narrowest visible tick gap instead of the first interval; linear scales choose the same step as before.

### Editing behavior

- Gantt controlled props are watched by reference. Pass fresh arrays and objects; in-place mutations do not trigger validation or cancel active edits.
- Editable Gantt bars emit `select` once per click, on release, including after a drag.
- Gantt pointer edits scroll automatically near horizontal viewport edges. Set `autoScroll` to `false` to disable this behavior.
